## Rulings

1. **A string with a lone surrogate round-trips exactly on the binary wire.** UTF-8 cannot carry one: msgpackr (2.1.0) writes a short string's code units raw (an invalid packet) and a long string through the UTF-8 encoder (U+FFFD, silently). Reproduce both first. `encodeBinary` walks the message once and tests each string with `String.prototype.isWellFormed()`; only when one fails does it pack a transformed copy in which each such string (value or map key) is carried as a MessagePack extension (one registered type code, its payload the string's UTF-16LE code units), and the decoder turns that extension back into the identical string. Canonical checking still holds: the decoded value re-encodes to the same bytes. A map key that is ill-formed is carried the same way (verify msgpackr can decode an ext as a map key into a string key; if it cannot, refuse such a message at encode with `Protocol` / `transport/unencodable` and say so). Measure the walk's cost on the 12 MiB fixtures (bytes and JSON rows) and state it; if it exceeds ~10% of pack time, narrow it (e.g. only strings above msgpackr's short-string threshold need the check, the short path can be detected in the canonical check) and record the choice. The JSON protocol already carries a lone surrogate exactly (JSON escapes it) — pin that too.
2. **The client's refusal of a host's answer carries `reason: "transport/answer-refused"`.** Where installment 7 made the client's schema refusal of a response a typed `Protocol` (the `isSchemaError` branch in `Binding.ts`), add the reason; the host ran. `docs/api.md`'s reasons list gains it.
3. **`Testing.client(capability, handlers, { tamper })` corrupts one message on purpose.** `tamper: { answer?: (tag: string) => boolean; request?: (tag: string) => boolean }` rewrites the matching answer (owner → client) or request (client → owner) into a packet that parses but is not canonical — the marker rewrite `undecodable.test.ts` uses — so the call fails typed exactly as a genuinely undecodable message does, and other calls continue. The same option on `Testing.layer`. Documented in `docs/testing.md` as a test door only.
